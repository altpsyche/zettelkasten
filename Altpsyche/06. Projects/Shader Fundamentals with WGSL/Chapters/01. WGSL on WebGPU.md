## Draft

### Intro

The GPU takes no instructions from you directly. A graphics API sits in between, and it determines the shader language you write. WGSL exists because of a particular API, WebGPU, and that API exists because of a particular problem.

In 1992 Silicon Graphics released OpenGL, and its shaders are written in GLSL. One API, one language, running on whatever hardware you had. Microsoft answered with DirectX and HLSL, so the world split in two. Two was manageable.

Then the hardware moved. GPUs stopped resembling the machines OpenGL had been designed to talk to, and the abstraction started costing real performance. The answer came from three directions at once, and it was to throw the abstraction out. Apple built Metal and MSL. Khronos built Vulkan, which takes SPIR-V. Microsoft built DirectX 12, keeping HLSL. Each is faster than what it replaced. Each runs on exactly one platform family.

Three APIs, three shading languages, and no way to write one shader that runs everywhere.

WebGPU is the portability put back. One API on top of Vulkan, Metal and DirectX, translating your calls into whichever of the three is underneath. One shading language with it, WGSL, compiled down to whatever the platform below expects.

The name misleads on two counts, so both are worth stating plainly.

First, WebGPU is not a new low level API competing with Vulkan. It is a layer over the three that already exist. That is how it manages to be portable and fast at the same time.

Second, WebGPU is not confined to browsers. It runs in browsers through JavaScript, TypeScript and WebAssembly. It runs in Node. It runs natively through Dawn for C and C++, and through wgpu for Rust, with community bindings past those. Bevy, the Rust game engine, is built on wgpu.

Against WebGL, the browser API it replaces, WebGPU adds compute shaders, indirect drawing, render bundles, external textures, better canvas integration and better debugging. Most of that list belongs to renderer work. Compute is the one this series comes back to.

It also drops global state. In WebGL you bind a buffer, bind a texture, select a program, and the draw call uses whatever happened to be bound. Nothing in the draw call says what it is drawing with, so a function that works alone breaks when something else ran first and left the wrong thing bound. WebGPU makes you declare the inputs up front instead.


## Summary

- A graphics API determines the shader language. OpenGL has GLSL, DirectX has HLSL, Metal has MSL, Vulkan takes SPIR-V.
- The three modern APIs each run on one platform family. Portability was what they cost.
- WebGPU is a layer over Vulkan, Metal and DirectX, not a competitor to them. WGSL is its language.
- WebGPU is not browser only. It runs in Node, and natively through Dawn and wgpu.
- It drops global state, so a draw declares its own inputs instead of inheriting them.
